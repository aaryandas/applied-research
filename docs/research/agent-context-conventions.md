# Agent context conventions: what Claude Code, Codex and Cursor read, and how they take an MCP server (2026-09-05)

Scope: first-party documentation only, read on 2026-09-05. Every claim carries its URL. "Not documented" means the page checked does not say it; it is not a claim that the behavior is absent. Product under test: the Context pack (`AGENTS.md` + `SKILL.md` + `references/`) and the local MCP server in `docs/mvp-prd.md` §9.

## (a) Claude Code

**Files read automatically.** `CLAUDE.md` in four scopes, loaded broad-to-specific and concatenated (never overriding): managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md` on macOS), `~/.claude/CLAUDE.md`, `./CLAUDE.md` or `./.claude/CLAUDE.md`, `./CLAUDE.local.md`. Files in the cwd and every ancestor load at launch; files in subdirectories load "when Claude reads files in those subdirectories". Within a directory `CLAUDE.local.md` is appended after `CLAUDE.md`. Block-level HTML comments are stripped before injection ([memory](https://code.claude.com/docs/en/memory)).

**Imports.** `@path/to/import` anywhere in a CLAUDE.md; relative paths resolve against the file containing the import; recursion to "a maximum depth of four hops"; imports inside backticks or fenced code are skipped. An import that resolves outside the working directory is "external" and triggers a one-time approval dialog in project-scope files. Imported files "still load and enter the context window at launch", so imports organise, they do not save tokens ([memory](https://code.claude.com/docs/en/memory)).

**AGENTS.md.** Verbatim: "Claude Code reads `CLAUDE.md`, not `AGENTS.md`." The documented bridge is a CLAUDE.md containing `@AGENTS.md` (plus Claude-specific lines below it) or `ln -s AGENTS.md CLAUDE.md`. `/init` reads `.cursor/rules/`, `.cursorrules` and `.github/copilot-instructions.md`; with `CLAUDE_CODE_NEW_INIT=1` it also reads `AGENTS.md`, `.devin/rules/`, `.windsurf/rules/`, `.clinerules`. `/import` (v2.1.213+) appends a one-time copy of `AGENTS.md` to `CLAUDE.md` and carries over MCP servers, commands, subagents and skills ([memory](https://code.claude.com/docs/en/memory)).

**`.claude/rules/`.** Exists. All `.md` files under `.claude/rules/` are discovered recursively; a rule without `paths:` frontmatter "loads at launch with the same priority as `.claude/CLAUDE.md`"; with `paths:` (glob list, brace expansion budget 1,000 patterns / 4 MiB) it loads when Claude reads a matching file. `~/.claude/rules/` is user-level and loads before project rules. Symlinked rules are followed ([memory](https://code.claude.com/docs/en/memory)).

**Size.** "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Hard limit: "Claude Code loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file." `/doctor` proposes trims that cut "directory layouts, dependency lists, and architecture overviews" and keep "pitfalls, rationale, and conventions that differ from tool defaults" ([memory](https://code.claude.com/docs/en/memory)).

**Skills (`SKILL.md`).** Locations, highest precedence first: enterprise managed dir, `~/.claude/skills/<name>/SKILL.md`, `.claude/skills/<name>/SKILL.md`, plugin `skills/`. At startup `.claude/skills/` from the start directory up to the repo root loads; nested `.claude/skills/` in subdirectories load when Claude first touches a file there. Only `name` + `description` (+ `when_to_use`) enter context at startup; the listing caps the combined description text at 1,536 characters per skill (`skillListingMaxDescChars`) and the whole listing at 1% of the context window (`skillListingBudgetFraction`); when the budget is exhausted descriptions are dropped, names kept. For personal and project skills `name` is display-only: "the command name is the directory name". Body: "Keep `SKILL.md` under 500 lines"; after auto-compaction a skill is re-attached up to 5,000 tokens, 25,000 tokens across all skills. Supporting files in the skill directory load only when Claude reads them. Claude-Code-only frontmatter (`disable-model-invocation`, `user-invocable`, `context`, `agent`, `paths`, `hooks`, `model`, `effort`, `arguments`, `argument-hint`, `shell`) causes a hard error on claude.ai upload; only `name, description, license, compatibility, metadata, allowed-tools` are portable. Verbatim: "Skills are **not** MCP servers; both can coexist. MCP servers provide tools; skills are instruction bundles." ([skills](https://code.claude.com/docs/en/skills)).

**MCP registration.** stdio: `claude mcp add [--env K=V] <name> -- <cmd> [args]` (the `--` is required). HTTP: `claude mcp add --transport http <name> <url> --header "Authorization: Bearer TOKEN"` (`-H` repeatable). `--transport sse` exists but "The SSE (Server-Sent Events) transport is deprecated. Use HTTP servers instead". Scopes: `local` (default, `~/.claude.json` under the project key), `project` (`.mcp.json` at repo root, committed, needs one-time approval), `user` (`~/.claude.json`). `.mcp.json` entries: `{"type":"http","url":…,"headers":{…}}` or `{"type":"stdio","command":…,"args":[…],"env":{…}}`; `${VAR}` and `${VAR:-default}` expand in `command, args, env, url, headers`; `headersHelper` runs a script that prints a JSON header map; OAuth via `claude mcp login`. Tools appear as `mcp__<server>__<tool>`. Tool results: warning at 10,000 tokens, default max 25,000 (`MAX_MCP_OUTPUT_TOKENS`), per-tool override via `_meta.anthropic/maxResultSizeChars` up to 500,000 chars ([mcp](https://code.claude.com/docs/en/mcp)).

## (b) OpenAI Codex (CLI, IDE extension, ChatGPT desktop app)

**AGENTS.md discovery.** Global first: `~/.codex/AGENTS.override.md`, else `~/.codex/AGENTS.md` (first non-empty wins). Then project: "from the project root (typically the Git root), Codex walks down to your current working directory"; in each directory it takes at most one file, trying `AGENTS.override.md`, then `AGENTS.md`, then names in `project_doc_fallback_filenames`. Files are concatenated root-first so the closest file appears last. Directories above the project root are not read. Verbatim: "Codex skips empty files and stops adding files once the combined size reaches the limit defined by `project_doc_max_bytes` (32 KiB by default)." and "Raise the limit or split instructions across nested directories when you hit the cap." ([AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). Config keys: `project_doc_max_bytes` ("Maximum bytes read from `AGENTS.md`"), `project_doc_fallback_filenames` ("Additional filenames to try when `AGENTS.md` is missing"; docs example `["TEAM_GUIDE.md", ".agents.md"]`), `project_root_markers` ([config reference](https://learn.chatgpt.com/docs/config-file/config-reference)).

**CLAUDE.md.** Not read by default. `CLAUDE.md` is not named anywhere on the AGENTS.md page; a user could add it to `project_doc_fallback_filenames`, and it would then be used only in a directory that has no `AGENTS.md`. No `@import` syntax is documented for AGENTS.md. No length guidance beyond the 32 KiB cap; content guidance is limited to examples ("working agreements", "repository expectations") ([AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).

**Skills.** Scan order: `$CWD/.agents/skills`, parent directories' `.agents/skills` up to the repo root, `$HOME/.agents/skills`, `/etc/codex/skills`, then bundled system skills. `.codex/skills` is not mentioned. Required frontmatter: `name`, `description`. Optional `agents/openai.yaml` beside `SKILL.md` carries `interface` (display_name, short_description, default_prompt…), `policy.allow_implicit_invocation` (default true; false forces explicit `$skill`), and `dependencies.tools` entries of `type: "mcp"` with `value` (server name), `transport: "streamable_http"`, `url`. The skills list "uses at most 2% of the model's context window, or 8,000 characters when the context window is unknown." No body-length guidance. Skills "build on the open agent skills standard" (agentskills.io) and work in Codex CLI and Codex in the ChatGPT desktop app ([build skills](https://learn.chatgpt.com/docs/build-skills)).

**MCP registration.** stdio: `codex mcp add <name> --env K=V -- <cmd> [args]`. HTTP: `codex mcp add <name> --url <url> [--bearer-token-env-var VAR]`; `codex mcp login <name>` for OAuth. Config lives in `~/.codex/config.toml` (or project `.codex/config.toml`) and is shared by CLI, IDE extension and desktop app. `[mcp_servers.<id>]` keys: `command, args, env, cwd` (stdio); `url, bearer_token_env_var, http_headers` (static map), `env_http_headers` (header→env var), `auth` (`oauth` | `chatgpt`); common `startup_timeout_sec` (default 10), `tool_timeout_sec` (default 60), `enabled`, `enabled_tools`, `disabled_tools`, per-tool `tools.<tool>.approval_mode` and `tools.<tool>.output_token_limit` ([MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [config reference](https://learn.chatgpt.com/docs/config-file/config-reference)). SSE: not documented. The GitHub README no longer documents AGENTS.md, MCP or skills; it links to the docs site ([README](https://raw.githubusercontent.com/openai/codex/main/README.md)).

## (c) Cursor

**Rules.** `.cursor/rules/*.mdc` with frontmatter `description`, `globs`, `alwaysApply`. Verbatim: "A plain `.md` file in `.cursor/rules` is ignored by the rules system because it has no frontmatter". Four types: Always (`alwaysApply: true`), Apply Intelligently (description, agent decides), Apply to Specific Files (`globs`), Manual (@-mention only). Order: "Team Rules → Project Rules → User Rules". Rules can `@filename` other files into context. Best practices, verbatim list: "Keep rules under 500 lines"; "Split large rules into multiple, composable rules"; "Provide concrete examples or referenced files"; "Avoid vague guidance. Write rules like clear internal docs"; "Reference files instead of copying their contents—this keeps rules short and prevents them from becoming stale as code changes" ([rules](https://cursor.com/docs/context/rules)).

**AGENTS.md.** "`AGENTS.md` is a simple markdown file for defining agent instructions … a plain markdown file without metadata"; "Cursor supports AGENTS.md in the project root and subdirectories"; nested files apply "when working with files in that directory or its children", combined with parents, "more specific instructions taking precedence" ([rules](https://cursor.com/docs/context/rules)). **CLAUDE.md:** the CLI page says "The CLI also reads `AGENTS.md` and `CLAUDE.md` at the project root (if present) and applies them as rules alongside `.cursor/rules`" ([CLI](https://cursor.com/docs/cli/using)); the editor rules page does not mention CLAUDE.md, so editor support is not documented. `.cursorrules`: absent from the current rules page; status not documented.

**Skills.** Supported. Project: `.agents/skills/`, `.cursor/skills/`; user: `~/.agents/skills/`, `~/.cursor/skills/`; "legacy compatibility": `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/`. Frontmatter read: `name` (lowercase, matches folder), `description`, optional `paths`, `disable-model-invocation`, `icon`, `color`, `metadata`. Nested skill directories are discovered recursively. Whether a skill can reference MCP tools: not documented ([skills](https://cursor.com/docs/context/skills)).

**MCP registration.** `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (global). stdio: `command` (required), `args`, `env`, `envFile`. Remote: `url` (required), `headers`, `auth` (static OAuth: CLIENT_ID, CLIENT_SECRET, scopes). Transports listed: stdio, SSE, Streamable HTTP. Interpolation: `${env:NAME}`, `${userHome}`, `${workspaceFolder}`, `${workspaceFolderBasename}`. Capabilities: tools, prompts, resources, roots, elicitation, Apps ([mcp](https://cursor.com/docs/context/mcp)).

## (d) Cross-agent summary and the MCP wire spec

| | Claude Code | Codex | Cursor |
|---|---|---|---|
| Reads `AGENTS.md` natively | No (`@AGENTS.md` import or symlink) | Yes, git root → cwd, one file per dir | Yes, root + nested |
| Reads `CLAUDE.md` | Yes, ancestors at launch, subdirs on demand | No (unless added to fallback list) | CLI: root only; editor: not documented |
| Import syntax | `@path`, 4 hops | none documented | `@filename` inside `.mdc` rules only |
| Size guidance | <200 lines target; 4 MiB skip | 32 KiB total chain, then stops adding | <500 lines per rule |
| Skill dir it discovers | `.claude/skills/` | `.agents/skills/` | `.agents/skills/`, `.cursor/skills/`, legacy `.claude/skills/`, `.codex/skills/` |
| Skill listing budget | 1,536 chars/skill; 1% of context | 2% of context or 8,000 chars | not documented |
| MCP stdio | `claude mcp add n -- cmd` | `codex mcp add n -- cmd` | `command/args/env` |
| MCP HTTP + bearer | `--transport http --header "Authorization: Bearer …"`; `${VAR}` in `.mcp.json` | `--url` + `bearer_token_env_var` or `http_headers` | `url` + `headers`, `${env:NAME}` |
| SSE | deprecated | not documented | listed |

Nothing reads `AGENTS.md` in all three; a root `CLAUDE.md` containing `@AGENTS.md` is the documented way to make one file serve all three.

**MCP spec 2026-07-28** (current). Two standard transports: stdio (newline-delimited JSON-RPC over the subprocess's stdin/stdout; server may log to stderr; "MUST NOT write anything to its `stdout` that is not a valid MCP message") and Streamable HTTP (single endpoint, POST only; reply is one JSON object or a request-scoped SSE stream). This revision removed the `initialize` handshake, protocol-level sessions and the `Mcp-Session-Id` header, the GET stream, and SSE resumability; every request carries `_meta.io.modelcontextprotocol/protocolVersion` and clients; servers MUST implement `server/discover`. Required HTTP headers: `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`. Security, verbatim: servers "**MUST** validate the `Origin` header on all incoming connections to prevent DNS rebinding attacks" (403 on invalid); "When running locally, servers **SHOULD** bind only to localhost (127.0.0.1)"; "Servers **SHOULD** implement proper authentication for all connections." The 2024-11-05 HTTP+SSE transport is Deprecated with a minimum twelve-month removal window. Roots, Sampling and Logging are deprecated ([transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [streamable-http](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)).

**TypeScript SDK v2** implements 2026-07-28 and is split into `@modelcontextprotocol/server`, `@modelcontextprotocol/client`, plus adapters `@modelcontextprotocol/node|express|fastify|hono`. Node usage per the package README: `new NodeStreamableHTTPServerTransport({ sessionIdGenerator: undefined })` for stateless operation, guarded by `localhostHostValidation()` and `localhostOriginValidation()` (or `hostHeaderValidation(allowedHostnames)` / `originValidation(...)`), `listen(port, '127.0.0.1')`; stdio via `StdioServerTransport` from `@modelcontextprotocol/server/stdio` ([SDK README](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/main/README.md), [node README](https://unpkg.com/@modelcontextprotocol/node/README.md)). Whether Claude Code, Codex and Cursor clients already speak 2026-07-28 (vs. falling back to `initialize`): not documented on any of the three vendors' MCP pages; the SDK's version-negotiation fallback is what makes this safe either way.

## (e) What the vendors say makes a context file effective

- **Anthropic.** "Keep it concise. For each line, ask: *Would removing this cause Claude to make mistakes?* If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" Include: commands Claude can't guess, style rules that differ from defaults, test instructions, repo etiquette, project-specific architectural decisions, env quirks, gotchas. Exclude: "Anything Claude can figure out by reading code", "Detailed API documentation (link to docs instead)", "Information that changes frequently", "Long explanations or tutorials", "File-by-file descriptions of the codebase". Use headers and bullets; write instructions "concrete enough to verify"; emphasis ("IMPORTANT") on one line only; "only include things that apply broadly. For domain knowledge or workflows that are only relevant sometimes, use skills instead." ([best practices](https://code.claude.com/docs/en/best-practices), [memory](https://code.claude.com/docs/en/memory)).
- **OpenAI.** Only structural guidance: keep within the 32 KiB chain limit, split across nested directories, use `AGENTS.override.md` for temporary changes ([AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). agents.md (now stewarded by the Agentic AI Foundation under the Linux Foundation) frames it as "a README for agents"; typical sections: project overview, build/test commands, code style, testing, security, PR guidelines; "The closest AGENTS.md to the edited file wins; explicit user chat prompts override everything." No size guidance ([agents.md](https://agents.md/)).
- **Cursor.** "Keep rules under 500 lines"; "Reference files instead of copying their contents"; avoid copying style guides, documenting every command, edge cases, or duplicating codebase content ([rules](https://cursor.com/docs/context/rules)).
- **Agent Skills spec.** Metadata ~100 tokens at startup; body "< 5000 tokens recommended", "Keep your main `SKILL.md` under 500 lines"; move reference material to `references/`, "Keep individual reference files focused", one level deep from `SKILL.md` ([spec](https://agentskills.io/specification)).

## (f) Consequences for the Context pack

1. **A subdirectory `AGENTS.md` is not auto-read from the repo root by anyone.** Codex reads only the directories between git root and cwd; Cursor applies a nested `AGENTS.md` only when working on files in that directory; Claude Code does not read `AGENTS.md` at all. If the pack lives at `applied-research/AGENTS.md`, the export must also offer to write (or print) one pointer line into the root: `@applied-research/AGENTS.md` for `CLAUDE.md`, and for Codex/Cursor either a root `AGENTS.md` that inlines the pack's Brief and says "read `applied-research/AGENTS.md` before design work" (no import syntax exists) or the pack itself installed as the root `AGENTS.md` when the repo has none.
2. **The always-loaded file must be thin.** Every vendor says the same: link, don't copy; omit detailed documentation and things that change often. A 200-line `AGENTS.md` of quoted claims is precisely what Anthropic's exclude column and Cursor's "reference files instead of copying" reject, and it competes for Codex's 32 KiB chain with the repo's own `AGENTS.md`. Keep `AGENTS.md` to the Brief, the human's decisions verbatim, open questions, the disclaimer header, and two lines on how to get claims (skill name, MCP tool names, `references/` path). Target well under 200 lines and under ~8 KB; put the claim lists only in `references/<paper-id>.md` and behind the MCP tools.
3. **`SKILL.md` constraints (documented).** `name`: 1–64 chars, `a-z0-9-` only, no leading/trailing/consecutive hyphens, "Must match the parent directory name" (so the project slug must be sanitised and the directory named identically). `description`: 1–1024 chars, non-empty, states what and when, with trigger keywords; Claude Code truncates the listing at 1,536 chars combined and Codex budgets the whole list at 2% of context, so the first sentence must carry the trigger ("Use when designing, choosing a library, or writing code that touches <topic>"). Body: under 500 lines / ~5,000 tokens; supporting `references/` one level deep. Portable frontmatter only: `name, description, license, compatibility, metadata, allowed-tools`; no `paths`, `context`, `disable-model-invocation`. Location: write the skill directory to `.agents/skills/<name>/` (Codex + Cursor) and `.claude/skills/<name>/` (Claude Code); a bare `context-pack/SKILL.md` is discovered by nobody.
4. **Skills can describe the MCP tools.** The body may instruct "call `mcp__applied-research__search_claims` before asserting anything from the literature" (Claude Code tool name form) and `search_claims` (Codex/Cursor). Codex additionally accepts `agents/openai.yaml` with `dependencies.tools: [{type: mcp, value: applied-research, transport: streamable_http, url: http://127.0.0.1:<port>/mcp}]`; the other two have no equivalent, and Anthropic is explicit that skills are not MCP servers. Vendor guidance says the skill should hold the domain knowledge that does not belong in the always-loaded file; the `references/` directory of the spec is the natural home for `references/<paper-id>.md`.
5. **Registration recipes the app should print.** Claude Code: `claude mcp add --transport http applied-research http://127.0.0.1:<port>/mcp --header "Authorization: Bearer <token>"`, or a committed `.mcp.json` with `"headers": {"Authorization": "Bearer ${APPLIED_RESEARCH_TOKEN}"}`. Codex: `codex mcp add applied-research --url http://127.0.0.1:<port>/mcp --bearer-token-env-var APPLIED_RESEARCH_TOKEN`. Cursor: `.cursor/mcp.json` with `"url"` and `"headers": {"Authorization": "Bearer ${env:APPLIED_RESEARCH_TOKEN}"}`. All three support env-var indirection, so the token never needs to be written into a committed file. stdio is unnecessary: the server already runs inside the Electron app, and the loopback HTTP form is what all three document.
6. **Server obligations from the spec.** Validate `Origin` (403), bind `127.0.0.1`, require the bearer token, implement `server/discover`, return deterministic `tools/list` order, and cap tool output well under Claude Code's 25,000-token default (the PRD's 8k-token `get_paper` cap is fine; Codex users can lower `tools.<tool>.output_token_limit`). Add Host-header validation (the SDK's `localhostHostValidation()`), which the PRD does not mention.
