# Practical Work checkpoint

Import `PracticalWork` from `./PracticalWork`. It renders supplied activity context, prediction, attempt, reported result, a single selected evidence reference, separately authored reflection and an explicit return action. No example curriculum or production adapter is supplied. The READY `PracticalTarget`, `PracticalGuidanceRequest` and `PracticalActivity` contract shapes remain unchanged by the component repairs.

## Scope and loading

The shell owns the attempt UUID and immutable activity context. The component remount key includes project, full path/topic/lesson/revision origin, source/highlight origin and attempt. It snapshots mounted activity and emits detached activity copies so a consumer cannot mutate the save origin through a guidance request. This guard does not replace the shell's obligation to flush before replacing scope. `initialDraft` is a previously acknowledged snapshot; omit it for an empty new attempt. Keep the commit adapter and its ownership fixed for that mount.

`activityStatus` optionally distinguishes `loading`/`unavailable` from the normal empty `activity: null` state. Once an activity is mounted, keep it mounted during evidence refresh rather than replacing it with the activity-loading screen and dropping its draft. The shell must load all metadata owned by this attempt: every previously selected/imported file and each trusted measured capture offer. Supply that complete collection in `returnedEvidence`; it is not merely a list of newly returned files. Set `evidenceStatus="loading"` while this collection is unresolved, `"unavailable"` on load failure, and `"ready"` only after the full collection has resolved. The optional status defaults to `ready` for existing callers that already load before mounting.

Loading has its own status and never produces a stale-reference alert. Only a missing selection in a ready collection is reported as no longer available. Loading, unavailable or missing selected metadata blocks both save and registered flush. Preserve the draft while the shell reloads metadata. A successful native selection joins the attempt's current metadata; it does not turn an in-progress refresh into ready.

## Saving and settlement

Keep `registerFlush` referentially stable. Before replacing project/activity, unmounting or quitting, await its callback and proceed only on `ready`; unregister on unmount. Flush waits for outstanding file/tool actions and drains saves, including edits made during a commit. A blocked flush preserves the mounted draft. Conflict latches for this mount: neither Save, Return nor repeated shell flush resends the stale expectedRevision, even after more writing. The shell owns explicit reconciliation: retain/copy the draft, load the current durable revision, let the learner resolve it, then mount the reconciled attempt. Reopening must not silently discard the preserved draft.

All injected asynchronous adapters must guarantee settlement. Main must return `null` for cancelled file selection, including when the owning window closes or quit cancels a pending dialog. Tool open/external callbacks must settle on success, refusal or failure. The bridge must reject requests when their IPC endpoint/owning window is lost, and each operation's producer must enforce its bounded completion policy. During quit the shell/main lifecycle must cancel pending dialogs before awaiting a flush that depends on their result. A never-settling adapter is invalid: this component intentionally has no timer, retry runtime or speculative cancellation engine that can pretend an uncertain operation completed.

`recordPracticalResult` must commit through a named main operation and acknowledge the same project/attempt only after durability. Main validates IDs, exact immutable origins, expected revision, field bounds and selected references in the transaction. Cancel/conflict/failure outcomes or rejected promises retain exact draft text. Raw adapter errors are replaced with safe UI copy. An ambiguous commit retry must be idempotent under stable attempt identity and unchanged content, because failure to receive an acknowledgement does not prove rollback. No legacy `saveEntry` fallback is appropriate.

`MAX_PRACTICAL_FIELD_LENGTH` in `draft-limits.ts` is the existing 12,000 UTF-16-code-unit bound for each human field. Main must enforce the same limit at its named-operation boundary. The UI retains a whole paste with no `maxLength` truncation, exposes a counter/invalid-field explanation and blocks persistence while any field exceeds the limit. Direct shell flush and queued edits during save have the same guard. It does not trim, normalize or silently clip the learner's writing. An over-limit flush uses the existing `failed` reason; a revision conflict keeps its existing `conflict` reason. No public flush enum is expanded.

## Evidence and tools

File selection is a named main selection/import callback returning opaque metadata or null for cancellation. Selection IDs resolve to bounded, project-owned imported content at commit. No renderer paths, file inputs or filesystem APIs. Measured offers come only from trusted measurement producers; the save payload contains a capture reference, never renderer measurements. Main verifies capture ownership/provenance; TypeScript tags alone are not a trust boundary.

Tool adapters supply supported embedded open/content and/or external open callbacks. Embedded content mounts in `.practical-embedded` only after a successful open. Practical styling uses explicit owned classes, so composed ToolPanel buttons/labels/forms/sections retain their own styles and layout. The shell owns guest lifecycle and navigation policy. LocalExplanations currently drops captures and is not a result adapter. This module neither edits nor silently connects those components.

## Guidance and companion-owned context

Guidance requests occur only when the learner clicks an available “Ask about…” action. Human-reported text alone makes selected-result guidance available; it remains explicitly user-reported and is never promoted to measured evidence. The request identifies the original activity/attempt and one existing app-scoped target, without collecting content, subscribing to observation or authorizing outside-app control. DOM attributes are positioning/test hooks, not a context API.

Saved-versus-draft reflection must come from the producer-owned context resolver, not the request. The companion author owns `CompanionResolution`, `CompanionContext` and `CompanionVersion` in its separately frozen contract checkpoint. Wait for root Fable review/release before implementing Practical’s optional resolver registration against that contract. The coordinator has explicitly separated that additive patch from these component repairs. No duplicate target/context enum or resolver is introduced here; an earlier temporary proposal is superseded and must not be consumed.
