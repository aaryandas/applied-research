## Destination

`docs/gauntlet/SURFACES.md`: a surface specification a gauntlet loop can build from and a boutique product-design critic can grade against. For every surface it states: the user's job, how you arrive, the primary flow to the moment of understanding, every state (empty, loading, partial, failed, stale, unsupported), what the AI may do and what only the human does, the keyboard grammar, the reference bar it is compared against, and how it connects to the other surfaces through the event log. Done when nothing about what the surfaces *are* remains undecided. It does not decide implementation.

## Not yet specified

- **Feel of the narrowing dialogue and the opening arrival.** Prototype candidates once "Start from a question" and "Opening screen and first run" resolve; sharp enough to ticket only after those decide what is on screen.
- **Owned-textbook reading.** How an EPUB/PDF the user owns presents (chapters as sources? one source with sections?), and how a course's readings link to it. Waits on the courses research and multi-source ticket.
- **Lecture transcripts as a reading form.** Whether the reader shows text only, text with a timestamp column, or embedded media; depends on what open courses actually expose.
- **Expertise across projects.** Insights and theses today belong to one project's Canvas; whether a field-level view spans projects (the vault as a body of expertise) is a later effort's question.
- **Paid-tier presence on surfaces.** Sync status, managed keys, cloud compute as they appear to the user (not the protocol). Waits on Settings and the shell.
- **Learning Path from a single paper.** When a project starts from a source, the first tree comes from that source's structure (as in the Wondering learning map); how it grows as sources are added is the Learning Path ticket's call.
- **Light theme per surface.** Token values are out of scope; whether any surface behaves differently in light is not; may need a line per surface.
- **Re-import of a source.** Parked on 2026-09-06 as not important now: sources are immutable, so stale anchors cannot occur. If a re-import flow is ever wanted, the recorded recommendation is user-triggered only, automatic re-anchoring where quoted text matches, stale marks with 'Find in source' for the rest.
- **Analytics disclosure moment.** Analytics is on by default and content never leaves the machine; where the user learns this (first run, Settings, both) is likely settled by the first-run ticket.
