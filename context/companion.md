# Companion · AR-25

The September 8 founder delegation in [the handoff](design-handoff/README.md) releases ordinary companion design decisions. This implementation uses the current renderer's accepted handoff tokens, typefaces and shared `FieldAtlas` mark. The older design-system specimen is historical where the handoff supersedes it. No dedicated companion screen was frozen; the criteria below define the delegated surface. [Product requirements](presearch.md) continue to prohibit observation merely because the companion is present.

## Owned behavior

- A decorative, non-interactive mark follows app-owned cursor events at most once per animation frame. Touch does not move it; reduced motion, blur, surface exit and host-reported native guest occlusion park it. The companion does not follow outside the app or read a native guest. Coordinates never enter context or guidance requests.
- Cmd/Ctrl+J opens ordinary keyboard-accessible controls. Ask resolves exactly one selected Practical target for one immutable project/origin/attempt. Opening the disclosure, typing and pointing do not resolve content. No global keyboard listener, automatic retry or typing subscription exists.
- Guide starts with an explicit action and becomes active only after an actual nonempty bounded response. The authorized target and Stop stay visible outside the disclosure. Cancel answer remains available when the disclosure closes; Stop/Cancel returns focus to the command. Requests remain disabled while physical cancellation settles.
- Only a tool-controls start bound to a host-owned tool session permits navigation cues. Completed changed URLs are throttled to one cue per 15 seconds and consumed even when busy. Navigation during start cancels it; later navigation discards pending old tool cues. Tool identity/URL must match the current host metadata. Page access is always `none`.
- Human reflection/report text and saved-versus-draft markers are preserved. Selected evidence retains its opaque original reference and trusted provenance identifier. Answers are read-only AI guidance, labelled separately from human, imported and app-measured material. There is no human-write/adoption callback and no mastery claim.
- Explicit semantic pointing reveals one producer-owned target, focuses its actual control and outlines validated viewport-clipped geometry. Missing geometry is unavailable. The consumer does not discover DOM text/selectors, inspect guest content or execute AI coordinates. Stop, selection/host invalidation, scrolling after reveal, resize, blur and teardown clear it.
- Missing resolver/selection, resolving/requesting, cancellation settlement, unavailable/stale, offline, unauthenticated, error and explicit retry states are visible. A fresh session always starts with guidance off. The module persists neither context nor consent.

## Integration ownership and exact contract

[The consumer README](../src/renderer/companion/README.md) specifies the complete wiring and producer constraints. The public types are in `src/contracts/companion.ts`; existing Practical types are unchanged.

**AR-19** supplies a stable mounted `resolveTarget(request, signal): Promise<CompanionResolution>`, registered through an optional `registerGuidanceResolver?: RegisterCompanionResolver`. The implementation reads only the explicitly selected owned instructions, controls, selected result or human reflection; rejects foreign origin/attempt identity; reports saved/draft state honestly; and resolves evidence through trusted ownership checks. Target availability updates are metadata only. Unmount removes the registration. Direct owned refs and an invalidation subscription implement the optional reveal interface.

**AR-37** mounts one `createCompanionRequester` and `Companion` per immutable attempt, passes `requester.registerResolver` to Practical, forwards explicit requests to `requester.session.askOnce`, and supplies a stable selected request or null. The host supplies an authenticated, abortable, runtime-validated `requestGuidance` adapter with per-request identity and evidence ownership verification. Existing legacy tutor/global stop operations are not compatible substitutes. The host forwards only navigation from the fixed real tool subscription; this metadata may update locally while guidance is off and never authorizes context reads by itself.

Before project/attempt replacement, activity completion, external handoff, tool close, sign-out or window teardown: invalidate target geometry and synchronously stop the session, then await the existing Practical flush before replacing content. A blocked save retains the human draft with guidance revoked. Remove the navigation subscription and dispose the requester on permanent teardown. The host must not restore observation automatically after restart, failed save or reauthentication.

The controller does not supply fake default content or answers. Until these real producers and transport are mounted, the production shell has no newly connected AR-25 flow. Checkpoints on base `94340203891406d012028d4762ae15fbfe04e04a` authorize bounded consumer implementation, not prerequisite completion or connected acceptance.
