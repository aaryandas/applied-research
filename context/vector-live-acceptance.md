## Hard admission and durable accounting

The existing `src/backend/accounting.ts`/`schema.ts` ledger protects **LearningRequest generation per account and UTC month**. Its reserve/settle patterns are useful, but it is not an aggregate embedding budget and must not be reused through fake LearningRequest casts or a resettable synthetic account.

Implement one immutable allowance ID, for example `ar48-initial-embedding-evaluation-2026-09-09`, with **250,000 microusd total**, shared by all workers/runs/accounts and surviving restarts/month changes. Before execution, reconcile earlier evaluation charges/reservations. Unknown prior consumption is not zero. Lock the allowance while reserving, then release the transaction before network I/O. Admission invariant: committed + reserved/uncertain + proposed ceiling <= 250,000. No reset, replenishment, automatic new allowance, or per-run fresh $0.25.

Persist run ID, exclusive run lease, exact namespace ownership, source/generation hashes, operation input hash, attempt number, reserved ceiling, dispatched timestamp, response ID, cost/usage if returned, stage, and cleanup status. Persist vectors keyed by canonical revision/passage + embedding recipe, so completed duplicates do not re-embed. A logical input conflict fails; a running or uncertain operation is not blindly retried with a new ID.

For this first probe, limit to **two physical embedding HTTP requests**: a two-document batch and one query. Total input text including query instruction <= 8 KiB UTF-8; individual passage <= 2,000 UTF-16 characters; two persisted vector rows, 1024 dimensions; one isolated namespace. Reserve **1,000 microusd ($0.001) per embedding dispatch**. At a pinned maximum $0.01/million input tokens with zero per-request fee, even two full 32,768-token inputs cost under that reservation; the selected texts are much smaller. Confirm the endpoint's limits/rate before execution. Stop if its fee structure cannot be bounded by this reservation. The initial normal path reserves at most $0.002, inside the shared $0.25 ceiling. This is conservative admission, not a claim about actual billed cost. [OpenRouter model pricing and providers](https://openrouter.ai/qwen/qwen3-embedding-8b/providers)

Use the embeddings API provider preferences to freeze an available endpoint supporting requested parameters, with `allow_fallbacks:false`, `require_parameters:true`, and `max_price:{prompt:0.01,request:0}`. Resolve the exact provider slug from current official endpoint data; do not invent one or silently widen price/provider settings on failure. No SDK automatic retries. A dispatched request with a timeout, malformed vector response, missing usage/cost, or lost response retains its reservation. Release only demonstrably undispatched calls; settle trusted actual cost once, rounding upward to microusd. Cancellation does not prove the provider did not charge. [Provider price/routing preferences](https://openrouter.ai/docs/guides/routing/provider-selection)

The official embeddings schema supports `dimensions`, `encoding_format`, and provider preferences. Response `usage` and `usage.cost` are optional, so zero cannot be inferred when absent. Require complete, unique input-index mapping, exact model identity, 1024 finite nonzero f32-representable values per vector, and bounded response bytes. [Official OpenRouter embeddings schema](https://raw.githubusercontent.com/OpenRouterTeam/typescript-sdk/main/src/models/operations/createembeddings.ts)

Track turbopuffer usage separately: Launch is **$16/month minimum usage, not a hard ceiling**, and the $0.25 allowance is for embeddings. Permit at most **12 physical vector HTTP attempts total for the run**, of which at least five remain reserved for cleanup/reconciliation; normal path below uses five. Count multi-query branches separately in usage. No pinning, warm-cache calls, recall evaluation, sharding, scanning, or additional namespaces. Current transport silently permits three attempts per operation; AR-48 must meter/limit each dispatch, including retries. Persist returned billing counters and unknown attempts; do not claim these operation bounds establish a dollar hard cap without the current applicable vector rates. [Launch pricing](https://turbopuffer.com/pricing)

## Exact normal sequence

1. **No-spend readiness:** freeze code SHA, model/generation, allowance balance, run ID, namespace mapping, passage hashes and expected result; validate exclusive ownership and cleanup capacity. Validate missing-config, allowance denial, wrong-dimension, cancellation, and cross-account behavior with fixtures before deployment. Do not use metadata GET as a free auth check: it is billed as a query. A nonexistent-namespace 404 alone is not sufficient authentication evidence. [Metadata API and billing](https://turbopuffer.com/docs/metadata)
2. **Acquire/validate source:** fetch the one exact public page through the existing acquisition guard, verify the pinned manifest, persist canonical authority, and select the two passages. No paid embedding before this succeeds.
3. **Embed documents, HTTP embedding #1:** reserve durably, dispatch `POST https://openrouter.ai/api/v1/embeddings` with `model:qwen/qwen3-embedding-8b`, `dimensions:1024`, `encoding_format:float`, input array of two plain document passages and frozen provider preferences. Validate and persist the returned vectors/receipt. Apply one versioned normalization recipe consistently. Query instructions belong on queries, not documents; use Qwen's recommended `Instruct: ...\nQuery: ...` form. A provider ignoring dimensions fails; do not silently truncate or substitute a model. [Qwen model-author usage guidance](https://huggingface.co/Qwen/Qwen3-Embedding-8B)
4. **Write, vector HTTP #1:** call production `indexBatch` for the two canonical `IndexPassage`s. Recheck durable authority immediately before dispatch. Existing payload supplies deterministic IDs, source_key/access_scope/generation, exact text/locators, cosine metric, `[1024]f32` ANN schema and BM25 text schema. Retain the accepted write receipt and billing counters. This successful operation begins evidence of real credentials/region/schema readiness. [Write API](https://turbopuffer.com/docs/write)
5. **Query, embedding #2 then vector HTTP #2:** ask a public, fixed question such as “Why can decimal fractions accumulate rounding error in binary floating-point arithmetic?” through the actual production query embedding path. Persist the real query vector. Call `retrieveEvidence` with only the authorized source revision, maxPassages=2, and strong ANN+BM25 multi-query. Require the predetermined supporting passage and verify quote, offset, revision/hash, scope, retriever provenance, and source title. Record branch rankings, fused rank, latency, and coverage. Do not invoke an LLM answer/support review. Strong queries include preceding writes; 409/index-lag is an explicit bounded failure, not permission for unlimited polling. [Query API](https://turbopuffer.com/docs/query)
6. **Replay and exclusion without provider calls:** replay completed embedding operation IDs and prove no additional dispatch. Mark only this run's corpus grant excluded in durable authority; call the public retrieval path again and require no evidence before embedding/network. A revoked/unauthorized source test proves the authority boundary. An unrelated semantic query is not a reliable no-evidence test: nearest-neighbor search still returns the closest available passage.
7. **Delete revision, vector HTTP #3:** stop new work and quiesce in-flight operations; preserve the tombstone and call existing `deleteRevision` using exact source/generation/scope. Validate completion, including any rows-remaining indication. Keep the source unusable if physical deletion fails.
8. **Confirm physical deletion, vector HTTP #4:** operator-only strongly consistent query of this exact owned namespace using the already persisted query vector and exact source/generation filter must return zero rows. This deliberately tests the remote store rather than the public adapter's earlier authority rejection. It must not re-embed.
9. **Purge owned namespace, vector HTTP #5:** call `DELETE /v2/namespaces/<exact-run-owned-namespace>` and require HTTP 200. Persist completion, then retire the namespace permanently in the run registry. Do not reuse it: a late write can recreate a deleted namespace. No blanket deletion/listing of other namespaces. A single bounded metadata read may reconcile an uncertain cleanup response, consuming the reserved attempt allowance; do not poll continuously. [Delete namespace API](https://turbopuffer.com/docs/delete-namespace)

On any failure after a possible write, enter cleanup using the already-owned namespace and reserved cleanup attempts. Never re-run acquisition/embedding to perform cleanup. An uncertain write may still commit after cancellation; serialize and reconcile it before purge, or retain a durable tombstone plus pending cleanup state and a finite reconciliation attempt. Do not call the run clean while remote completion remains unknown. Cleanup failure must remain visible and recoverable under the same run/allowance IDs.
